# Контрольный список расширения REST

## До кода

- Проверить установленный модуль `rest` и найти фактическое использование `OnRestServiceBuildDescription` в проекте и ядре.
- Зафиксировать имя метода, scope, потребителей, права, вход и результат.
- Проверить, нельзя ли использовать или композиционно обернуть штатный метод.

## Контракт

- Использовать уникальный префикс vendor/module.
- Ограничить поля фильтра, сортировки и выборки.
- Задать максимальный размер страницы и стабильный порядок.
- Вернуть публичную ошибку, пригодную для машинной обработки, без внутренних деталей.
- Для несовместимого изменения создать новую версию метода.

## Проверка

- Метод виден только в ожидаемом scope.
- Проверены права пользователя и бизнес-ограничения.
- Неверные типы, неизвестные поля и превышение лимита отклоняются.
- Нет SQL/ORM-инъекции, N+1 и неограниченной выборки.
- Повтор записи не создаёт непреднамеренные дубли.
- Старый потребитель продолжает работать.

## Источники истины

1. Код установленного модуля `/bitrix/modules/rest`.
2. Существующая регистрация REST в `/local/modules`.
3. D7 API модуля REST: <https://dev.1c-bitrix.ru/api_d7/bitrix/rest/>.
4. Документация Bitrix24 REST API: <https://apidocs.bitrix24.com/>.
